Neo4j Social Graph Relationship Visualizer

Demonstrates 1st-degree, 2nd-degree connections, and mutual friends query performance in Neo4j graph database.

MATCH (user:User {id: 'user_101'})-[:CONNECTED]-(mutual:User)-[:CONNECTED]-(secondDegree:User)
WHERE NOT (user)-[:CONNECTED]-(secondDegree) AND user <> secondDegree
RETURN secondDegree, COUNT(mutual) AS mutualCount, COLLECT(mutual.name) AS mutualFriends
ORDER BY mutualCount DESC LIMIT 10;

Redis Cache vs Relational DB Latency Benchmark

Comparing retrieval speed for 1,000 active follower feeds.

Redis Fan-Out Feed

1.8 ms

Direct O(1) key lookup in Redis in-memory cache.

  • No disk I/O bottleneck
  • No recursive connection JOIN queries
  • Pre-computed feed timeline

Relational SQL JOIN Query

340.5 ms

Scans millions of posts with WHERE author IN (friends)

  • High CPU utilization
  • Causes database lock contention under peak traffic
  • Degrades exponentially with connection count
